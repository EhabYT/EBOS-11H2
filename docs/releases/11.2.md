# EBOS 11.2

AME Wizard playbook, build label `20261008.fb75f1`.

Import `EBOS-v11.2.apbx` directly into AME Wizard; do not unpack it first.
Supported Windows builds: **19044, 19045, 22631, 26100, 26200, 26300**.
The list in `playbook.conf` matches the phase-1 build gate.

## Highlights

- Optional Windhawk taskbar/File Explorer styling and Offline Mode. Both new wizard
  options default to **unticked**. The stock Windhawk GUI installer is bundled;
  the separate CLI installer and compiled mod cache are not included in this source build.
- Per-user theme/HKCU application instead of relying on TrustedInstaller's own HKCU.
  `apply-hkcu-fanout.ps1` is generated from the YAML; do not hand-edit its data table.
- Post-apply verification covers expected registry/service/task/AppX/file state, including
  absence checks for deletes. Results are appended to `%WINDIR%\EBOS\ebos-skipped.txt`.

## Verification corrections

- Direct task registrations need an **`op='create'`** assertion. A matching name in a
  delete/disable row no longer passes build-time coverage. Task paths, case, quoted names,
  literal variables, line continuations and direct YAML caller gates are handled;
  unresolved names produce an error instead of disappearing from the audit.
- `EBOS Personalization Guard` and `EBOS-ResumeGuard` must be present and enabled.
  The verifier accepts `Ready`, `Running` or `Queued`, not `Disabled` or an unknown state.
  This is a state check, not proof that the task action or logon trigger executed.
- `EBOS-TimerResolution` and `GlobalTimerResolutionRequests` are checked **only on fresh
  installs**. Re-applying EBOS intentionally preserves the user's Dash choice. Phase 1
  records the pre-apply installation mode in `verify-context.json`, tied to the current
  option-file timestamp; phase 8 must not infer it from the stamp phase 7 just overwrote.
  A missing, stale or unreadable context is an explicit verification failure.
- A failed/partial `Get-ScheduledTask` enumeration reports **`TASK QUERY FAILED`**;
  it is not treated as proof that deleted tasks are absent.

Current verifier tables contain **697 registry-value rows, 110 service rows and 166 task
rows**. The task table has 3 create assertions, 7 absence assertions and 156 disable
expectations. The 7 native `!scheduledTask` actions are **6 deletes and 1 disable**;
this is not the same count as the full script-generated task table.

### Lifecycle exclusions — not verified success

Three registrations remain outside phase-8 presence assertions:

| Task | Why presence alone is not a stable end-state check |
|---|---|
| `EBOSDefenderCleanup` | Created during apply; unregisters only when cleanup folders are gone, possibly after multiple logons. |
| `EBOSDefenderRestartNotice` | Created during apply; unregisters when its first logon execution runs. |
| `EBOSDefenderKeepDisabled` | Registered by the deferred cleanup, not directly during apply. |

The first two **normally exist before the next logon**. Their omission is a documented
coverage limitation, not a claim that they are absent at verification time. Exclusions
are scoped to their source file and gate so unrelated registrations cannot reuse them.
Post-logon integration tests are still required.

`Explorer\StuckRects3\Settings` deletion is also excluded: Explorer recreates this live
state. Service starts written inside scripts, legacy registry-value deletes, wallpaper
pointers and branding values were added to the verifier in the preceding audit.

## Offline completeness

This artifact is **not an all-options offline bundle**. Missing build inputs:

| Asset | Consequence |
|---|---|
| `vc_redist.x64.exe` | Offline VC++ installation is skipped/logged; applications may lack the runtime. |
| `BraveSetup.exe` (or `brave-setup.exe`) | Offline Brave installation is skipped/logged; removing Edge too can leave no browser. |
| `windhawk-cli*-installer.exe` | On a clean offline machine, selected Windhawk styling fails its preflight with exit 3. |
| `windhawk-cache/` | Selected Windhawk styling needs both compiled Styler mods locally for an offline run. |

`windhawk_setup.exe` installs the GUI engine; **it is not a substitute for `whcli.exe`**.
The build now distinguishes them and rejects empty caches/missing mod DLLs under
`--require-bundles`. These are structural checks, not Authenticode or DLL execution tests.
Provision and validate the external files on Windows as described in `Executables/BUNDLES.md`.

## Archive encryption correction

The custom LZMA2 filter previously suppressed py7zr's automatic AES payload filter.
Headers were encrypted, so password-less listing failed, **but the file contents were
not encrypted**. This build explicitly includes AES-256 in the payload filter chain.
The builder now rejects header-only or payload-only encryption. Regression tests cover
both failures, and the CI recipe also inspects 7-Zip's per-file `Encrypted` field.

## Build and test

```bash
python3 -m pip install -r tools/requirements-build.txt
python3 -m unittest discover -s tools/tests -v
python3 tools/build-playbook.py --dry-run
python3 tools/build-playbook.py
```

For an offline-complete release, provision the bundles first and build with
`--require-bundles`. The build regenerates `BUILD-REPORT.md`, `SHA256SUMS.txt` and these
release notes beside the archive. The notes template is tracked in `docs/releases/11.2.md`.

The regression suite tests static coverage, bundle checks and CI shell behaviour without
calling GitHub. The PowerShell verifier tests use mocked reads and require PowerShell;
they explicitly skip when no interpreter is installed. Static checks and archive
integrity **do not establish a successful AME/Windows deployment**. Test on disposable
Windows VMs, including fresh install, re-apply, offline and subsequent-logon paths.

## Release automation

`tools/ci/release.yml` remains a recipe, not an enabled workflow. Once installed by an
authorized maintainer, it builds the exact requested tag and only creates/updates a
**draft** release. It does not publish or overwrite existing assets. The tag must contain
these tools and match `<Version>`; an older tag does not pick up newer branch fixes.
